# Площадка совместного использования

Индивидуальный сквозной проект по дисциплине **«Технологии разработки приложений на базе фреймворков»** (семестр 5).

---

## 1. Назначение проекта

Проект представляет собой сервис для учета и совместного использования бытовых вещей между соседями (жителями общежитий, коммунальных квартир или коливингов).

Сервис решает ключевую проблему потери и поиска предметов общего обихода: фиксирует текущего владельца каждой вещи, позволяет отправлять запросы на получение предметов, фиксирует передачу вещей из рук в руки и сохраняет прозрачную историю владения.

---

## 2. Целевая аудитория

Целевой аудиторией являются жители общежитий, студенческих кампусов и коммунальных квартир, где совместное использование бытовой техники (чайников, утюгов, пылесосов, инструментов) является привычной практикой и позволяет оптимизировать расходы на покупку дорогостоящих предметов.

---

## 3. Предметная область

Предметная область проекта — процесс временной передачи предметов быта между участниками сообщества с контролем владения, фиксацией статуса готовности к передаче и подтверждением запросов.

---

## 4. Основные сущности (Объектная модель ПР3)

В рамках перехода к объектно-ориентированному программированию (ПР3) выделены следующие ключевые сущности:

1. **User (Пользователь)**:
   - Атрибуты: `id`, `name`, `age`, `sex` (`Sex` Enum: `MALE`, `FEMALE`), список удерживаемых предметов `items`, список созданных запросов `requests`.
   - Методы: `login()`, `register()`, `__get_age__()`, `__get_sex__()`, `to_dict()`, `from_dict()`, `__str__()`.
2. **Item (Вещь / Предмет)**:
   - Атрибуты: `id`, `name`, `description`, `owner` (ссылка на объект `User` или `None`, если предмет свободен).
   - Методы: `own(user)` — закрепление вещи за пользователем, `free()` — освобождение вещи, `to_dict()`, `from_dict()`, `__str__()`.
3. **ItemRequest (Запрос на передачу)**:
   - Атрибуты: `id`, `item` (ссылка на `Item`), `old_user` (текущий владелец), `new_user` (запрашивающий пользователь), `status` (`ItemRequestStatus`: `PENDING`, `APPROVED`, `REJECTED`), `created_at`.
   - Методы: `try_accept()` — одобрение запроса и автоматическая передача вещи новому владельцу, `reject()` — отклонение запроса, `to_dict()`, `__str__()`.
4. **Transfer (Передача предмета)**:
   - Атрибуты: `id`, `item_id`, `from_user_id`, `to_user_id`, `transferred_at`, ссылки на объекты `item`, `from_user`, `to_user`.
   - Методы: `to_dict()`, `from_dict()`, `__str__()`.

## 6. Хранилище данных (ПР2–ПР3)

На этапах ПР2 и ПР3 реализовано сохранение данных в JSON-файлах в каталоге `data/`. Чтение и запись выполняются через контекстный менеджер `with open(...)` в модуле `storage.py`. При чтении восстанавливаются объектные связи между сущностями (владелец вещи, участники запроса и передачи).

Реализована обработка исключительных ситуаций: отсутствие файлов, пустые файлы, поврежденный формат JSON. На этапе перехода к веб-интерфейсу (ПР5–ПР6) данные продолжают считываться из JSON-хранилища в соответствии с методическими требованиями (переход на Django ORM запланирован на ПР7).

## 7. Веб-интерфейс на Django (ПР5–ПР6)

Веб-приложение создано на базе Django:

- **Локализация и параметры**: в `sharing_platform/settings.py` настроены параметры `LANGUAGE_CODE = 'ru-RU'`, `TIME_ZONE = 'Europe/Moscow'`, `USE_TZ = True`.
- **Маршрутизация**:
  - `/` — главная страница (`homepage:index`), сводная статистика сервиса, быстрые ссылки;
  - `/items/` — каталог вещей (`items:list`) с фильтрацией по статусу (все, свободные, занятые);
  - `/items/available/` — поиск свободных вещей по названию (`items:available`, ПР7);
  - `/items/<id>/` — детальная страница вещи (`items:detail`) с информацией о владельце и историей передач;
  - `/requests/` — реестр запросов на вещи и журнал состоявшихся передач (`item_requests:list`);
  - `/requests/statistics/` — аналитическая статистика популярности предметов (`item_requests:statistics`, ПР7);
  - `/requests/<id>/` — детальная страница запроса (`item_requests:detail`).
- **Обработка ошибки 404**: при обращении к несуществующему маршруту или объекту вызывается кастомный обработчик `custom_page_not_found`, возвращающий HTTP-статус 404 и отображающий стилизованный шаблон `templates/404.html`.
- **Система шаблонов (DTL)**:
  - Базовый шаблон `templates/base.html` с единой адаптивной навигацией, блоками `{% block title %}` и `{% block content %}`;
  - Включаемые компоненты `{% include %}`: `items/includes/item_card.html`, `item_requests/includes/request_status.html`;
  - Условные конструкции `{% if %}`, циклы `{% for %}`, обработка пустого списка `{% empty %}`;
  - Фильтры шаблонов (`length`, `date`);
  - Именованные ссылки с пространствами имен (`{% url '...' %}`);
  - Подключение Bootstrap 5.3 через CDN и собственных стилей `static/css/style.css` через `{% load static %}`.

## 8. Реляционная база данных SQLite и интеграция с веб-приложением (ПР7)

В рамках Практической работы № 7 осуществлен переход от файлового JSON-хранилища к реляционной базе данных SQLite:

1. **Реляционная схема (`sql/schema.sql`)**:
   - Активирован контроль внешних ключей (`PRAGMA foreign_keys = ON;`);
   - Таблица `users`: первичный ключ `id`, имя `name`, возраст `age`, пол `sex` с ограничением `CHECK (sex IN (0, 1))`;
   - Таблица `items`: первичный ключ `id`, название `name`, описание `description`, внешний ключ `owner_id REFERENCES users(id) ON DELETE SET NULL`;
   - Таблица `requests`: внешний ключ `item_id REFERENCES items(id) ON DELETE CASCADE`, `old_user_id` и `new_user_id` с `ON DELETE RESTRICT`, статус с проверкой `CHECK (status IN ('PENDING', 'APPROVED', 'REJECTED'))`, дата создания `created_at`;
   - Таблица `transfers`: история передач со связями к `items` (`ON DELETE CASCADE`) и участникам передачи `from_user_id`, `to_user_id` (`ON DELETE RESTRICT`).

2. **Демонстрационные SQL-запросы (`sql/queries.sql`)**:
   - Тип 1 (SELECT / ORDER BY): сортировка предметов по названию и пользователей по возрасту;
   - Тип 2 (WHERE): фильтрация свободных предметов (`owner_id IS NULL`) и заявок в ожидании (`PENDING`);
   - Тип 3 (JOIN): получение каталога с именами владельцев (`LEFT JOIN`) и реестра заявок со связанными предметами и именами участников;
   - Тип 4 (COUNT / Агрегаты): подсчет общего числа предметов, свободных и занятых предметов, диапазона дат передач;
   - Тип 5 (GROUP BY): группировка предметов по пользователям и заявок по предметам;
   - Тип 6 (HAVING / Подзапросы): фильтрация групп предметов с числом заявок более одной и выборка свободных предметов без активных заявок.

3. **Скрипт миграции данных (`db/import_json.py`)**:
   - Автоматически создает таблицы БД из `sql/schema.sql`;
   - Загружает сущности в строгом иерархическом порядке: `users` -> `items` -> `requests` -> `transfers`;
   - Обеспечивает идемпотентность повторного выполнения через конструкции `INSERT ... ON CONFLICT(id) DO UPDATE SET ...`;
   - Выполняет транзакционный импорт с автоматическим откатом (`conn.rollback()`) при ошибках.

4. **Интеграция со слоем представлений Django**:
   - Все контроллеры переведены на прямое взаимодействие с базой данных `data/sharing.sqlite` через `get_connection()`:
     - `homepage:index`: расчет статистики сервиса агрегатными SQL-запросами `COUNT(*)`, выборка недавних вещей и истории передач с `LIMIT`;
     - `items:list`: выборка вещей и имен владельцев через `LEFT JOIN users` с фильтрацией по статусу (`free`, `busy`, `all`);
     - `items:detail`: параметризованный запрос вещи по `id`, выборка истории передач и заявок через SQL с JOIN к пользователям;
     - `items:available` (`/items/available/`): поиск свободных вещей (`owner_id IS NULL`) с параметризованным фильтром `LIKE ?` по поисковой строке `q`;
     - `item_requests:list`: выборка заявок и журнала передач с объединением таблиц предметов и участников;
     - `item_requests:detail`: параметризованная выборка деталей заявки;
     - `item_requests:statistics` (`/requests/statistics/`): аналитический отчет с группировкой `GROUP BY` и фильтрацией групп `HAVING COUNT(requests.id) >= 1`.
   - Безопасное параметризованное выполнение запросов (`?`) с гарантированным освобождением соединений в блоках `try ... finally: conn.close()`.

## 9. Инструкция по запуску и тестированию

### Установка зависимостей

Проект использует виртуальное окружение Python (рекомендуется Python 3.11+ / 3.14):

```bash
uv sync
# или через стандартный pip:
pip install django flake8 pytest
```

### Инициализация базы данных и импорт данных (ПР7)

Для создания базы данных SQLite и загрузки начального набора данных из JSON-файлов:

```bash
uv run python -m db.import_json
```

База данных будет создана по пути `data/sharing.sqlite`.

### Запуск консольного приложения (ПР1–ПР3)

```bash
python main.py
```

Приложение предоставляет интерактивное меню:
1. Каталог всех вещей
2. Добавить новую вещь
3. Запросить вещь у соседа
4. Входящие запросы ко мне (с возможностью одобрения или отклонения)
5. Мои вещи
6. История передач
7. Сохранить данные в JSON
0. Выход

### Запуск веб-приложения Django (ПР5–ПР7)

Проверка конфигурации:
```bash
python manage.py check
```

Запуск сервера разработки:
```bash
python manage.py runserver
```

После запуска страницы доступны по адресам:
- Главная страница: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
- Каталог вещей: [http://127.0.0.1:8000/items/](http://127.0.0.1:8000/items/)
- Поиск свободных вещей: [http://127.0.0.1:8000/items/available/](http://127.0.0.1:8000/items/available/)
- Страница предмета: [http://127.0.0.1:8000/items/1/](http://127.0.0.1:8000/items/1/)
- Реестр запросов: [http://127.0.0.1:8000/requests/](http://127.0.0.1:8000/requests/)
- Статистика сервиса: [http://127.0.0.1:8000/requests/statistics/](http://127.0.0.1:8000/requests/statistics/)
- Страница запроса: [http://127.0.0.1:8000/requests/1/](http://127.0.0.1:8000/requests/1/)

### Запуск автоматизированных тестов

Автоматизированные тесты Pytest проверяют регистрацию, ООП-модели, хранилище данных, целостность реляционной БД SQLite и все Django-маршруты:

```bash
pytest
```

### Проверка качества кода (Линтер flake8)

Код оформлен в строгом соответствии с PEP 8 (длина строки не более 79 символов, аннотации типов, docstring):

```bash
flake8
```
